     ─ Unit tests para lógica de negocio
     ─ Integration tests para flujos con dependencias externas
     ─ Property tests para invariantes
     ─ Chaos tests para resiliencia
     ─ Performance tests para benchmarks
     ─ Security scan para CVEs/SAST

  P9.3 — Queue Position Modeling  [🟢 100% — PLANEAR ✅, CONSTRUIR ✅, TESTEAR ✅, DESPLEGAR ✅]
  ───────────────────────────────
  PLANEAR:
    ▸ Objetivo: Modelar la probabilidad de fill para órdenes MAKER (límite)
                basada en posición estimada en la cola del orderbook,
                permitiendo optimización maker-vs-taker.
    ▸ Problema actual: FillSimulator (P9.1) y SlippageEngine (P9.2) siempre
                asumen TAKER (crossing the spread). Ser MAKER elimina el
                costo del spread y el price impact, a cambio de riesgo de
                non-fill y adverse selection.
    ▸ Criterios de éxito:
      - Estimaciones de P(fill) dentro de ±15% de fills simulados
      - Decisión maker/taker reduce costo total de ejecución ≥5% vs taker-only
      - Modelo produce fill time distributions estables y reproducibles
      - Overhead < 1ms en el handler de ejecución
    ▸ Dependencias:
      - P9.1 (FillSimulator) — depth model del orderbook
      - P9.2 (SlippageEngine) — volatilidad y régimen para adverse selection
      - P8.1 (Parquet recording) — datos reales para calibrar turnover
      - P8.4 (RegimeClassifier) — clasificación de régimen para riesgo maker
    ▸ Riesgos:
      - Sin Level 3 data (no IDs de órdenes, eventos add/cancel/trade)
        → posición en cola es aproximada
      - Orderbooks de Polymarket tienen baja profundidad → ruido alto
      - Adverse selection puede dominar cualquier beneficio de maker
    ▸ Mitigaciones:
      - Usar volume_24h como proxy de tasa de turnover (robusto)
      - Fórmula de fill probability time-bounded con ventana T
      - Costo de adverse selection ≈ volatility × time_to_fill
      - Penalizar fuertemente maker en régimen PANIC/TREND
      - Fallback: volume_24h=0 → tasa de turnover ~0.01 USDC/sec
    ▸ Parámetros de diseño:
      - wait_time_T: tiempo máximo de espera del maker (default 30s,
        configurable por estrategia/asset)
      - delay_penalty: costo de oportunidad si el maker no llena =
        taker_slippage × missed_entry_factor (default 0.5)
      - mode: maker (siempre límite), taker (siempre mercado),
        auto (compara costos esperados)
    ▸ Flujo de decisión auto-mode:
      1. SlippageEngine.estimate(side="entry") → TakerCost
      2. SlippageEngine.estimate_maker(wait_time=T) → p_fill,
         adverse_selection
      3. MakerCost = (p_fill × adverse_selection)
         + (1-p_fill) × (TakerCost + delay_penalty)
      4. Si MakerCost < TakerCost × 0.95 → MAKER, else TAKER
    ▸ Contratos afectados: D-25 (paper slippage model)
